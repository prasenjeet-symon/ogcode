Why it's cheaper

Most of your AI bill is repeated history.

Naive agents bundle the whole transcript into every request. The bill grows linearly, and the model has to find three relevant facts inside a hundred stale messages. Ogcode pulls those three facts out of a persistent knowledge graph and sends only those.

Plan Mode

Describe a feature. Get pull requests.

Most agents stop at "here's the code for that file." Ogcode plans the feature with you, splits it into parallel-safe tasks, runs each in its own git worktree, and opens the PRs against your GitHub repo — designed not to conflict.

1 · Describe

Talk through the goal. The planner reads your codebase and pushes back on the approach.

2 · Lock

A breakdown agent turns the plan into tasks with S/M/L/XL estimates and a dependency graph.

3 · Review

Tasks land on a Kanban board. Reorder them, inspect them, or fire them off one at a time.

4 · Execute

Every task gets an isolated worktree and its own agent. Independent tasks run at the same time.

5 · Ship

Finished tasks commit, push, and open a PR via gh — idempotently, with a written body.

Parallel tasks never share a file

The breakdown agent is forbidden from letting two concurrent tasks touch the same file — if they would, it inserts a dependency instead. That's what keeps the PRs merge-clean.

Linear chains, no tangles

Each task depends on at most one other, producing clean A→B→C chains. Cycles are rejected before anything runs.

One PR per chain

Chained tasks share a branch and accumulate each step, so the chain raises a single consolidated PR instead of N conflicting ones.

Failures retry from clean

A failed task deletes its stale branch and starts fresh. Worktrees and branches are pruned on success, failure, retry, and crash recovery.

One binary

Everything else it does.

No extension to install, no daemon to babysit, no cloud account. A Go binary with the whole UI compiled in.

Any model you want

Claude, GPT, OpenRouter, or a local Ollama model — switched from the UI mid-session. No lock-in, no reseller markup.

Semantic codebase map

Every file is indexed with topic labels on first load, so the agent navigates straight to what matters instead of grepping blind.

Knowledge graph memory

Topic → Concept → Fact, persisted across sessions. Close the tab on Friday, pick the thread back up on Monday.

Approve before it acts

Writes, edits, and shell commands ask first, per tool. Read-only tools run freely. A bash denylist blocks the obviously destructive.

Diagrams, math, charts

Agents render Mermaid, LaTeX, Plotly, and live HTML/CSS/JS straight into the chat — not as a code block you paste elsewhere.

Deep research, cited

A built-in deep_search tool browses the web, reads the pages, and hands the agent a cited synthesis.

Quickstart

Running in about a minute.

No config file, no Docker required, no IDE extension.

STEP 01

Install

Drops a single binary on your PATH. Windows, Docker, and go install also work.

# macOS / Linux
curl -fsSL http://ogcode.xyz/install.sh | sh
STEP 02

Point it at a model

Any provider key — or skip this entirely and run a local model with Ollama, fully offline.

# hosted
export ANTHROPIC_API_KEY=sk-ant-…

# or local & free
ollama serve
STEP 03

Open it

Run it inside the repo you want to work on. It indexes the codebase and opens in your browser.

cd ~/code/my-project
ogcode

# → http://localhost:9595
FAQ

The questions people actually ask.

Does my source code leave my machine?
Only in the prompts you send to whichever model provider you chose — the same as any coding agent. There is no Ogcode server, no telemetry endpoint, and no account. Indexing, the knowledge graph, and session history all live in a local database. Pick a local Ollama model and nothing leaves the machine at all.
Can I really run it fully offline?
Yes. Ogcode auto-detects a running ollama on macOS and Linux, and can be pointed at one explicitly on any OS. Embeddings can also run locally. Offline you lose the deep_search web tool and hosted models — everything else works.
Is the 70% number real, or marketing?
It's measured against a naive full-replay loop across real sessions, and it scales with session length — about 68% at 50 messages, ~76% at 1,000. Short sessions save less because there's less history to avoid replaying. Enable it with OGCODE_AGENTIC_MEMORY_MODE=true. The mechanism and the numbers are both in the README, and the code is MIT — check it yourself.
If it drops old messages, does it forget things?
It doesn't drop them — it moves them. Facts are extracted into a persistent knowledge graph and recalled on demand, and stale stretches of history are compacted rather than truncated. In practice the model forgets less than a replay loop does, because a replay loop eventually runs out of window and starts genuinely losing the beginning of the conversation.
Does it work on Windows?
Yes — irm http://ogcode.xyz/install.ps1 | iex in PowerShell, or run the Docker image. Parallel task execution needs git, and auto-PRs need the GitHub CLI authenticated.
Can I run it on a server and use it from my laptop?
Yes. It's a normal HTTP server on port 9595, so put it behind nginx or Caddy with TLS and auth. Don't expose it to the open internet unprotected — the agent can run shell commands. Setup notes are in the remote deployment guide.
What does it cost?
Ogcode is free and MIT-licensed. You pay your model provider directly for tokens — which is rather the point of spending 70% fewer of them. With Ollama, it costs nothing.
I already use Claude Code / Cursor. Why switch?
You may not need to. Ogcode is strongest when sessions run long, when you want a feature planned and shipped as PRs rather than a file edited, or when you want to stay off a subscription and off the cloud. If you mostly want inline completions in your editor, keep what you have.
